# Jaaxis CLI

`jaaxis` is how a coding agent (Claude Code, Codex) or a person edits a merchant agent. An agent is a TypeScript project. `jaaxis pull` writes it to a folder, you edit the files, and `jaaxis push` type-checks, tests and saves them. It signs in the way an MCP client does and adds no permission of its own: every command is the same operation the dashboard assistant and hosted MCP run, authorized by the server.

Releases: `https://github.com/Jaaxis/jaaxis-cli/releases`.

## Install

macOS and Linux:

```bash
curl -fsSL https://github.com/Jaaxis/jaaxis-cli/releases/latest/download/install.sh | sh
```

Windows, in PowerShell:

```powershell
irm https://github.com/Jaaxis/jaaxis-cli/releases/latest/download/install.ps1 | iex
```

- It installs to `~/.jaaxis/bin/jaaxis` (Windows: `%USERPROFILE%\.jaaxis\bin\jaaxis.exe`) and puts that folder on `PATH`. No administrator rights.
- It installs only a build whose sha256 is in `checksums.txt`, and only when a Jaaxis release key signed that file (ECDSA P-256). A failed download or check installs nothing.
- It runs `jaaxis setup` once. It never installs over a newer build.
- Windows needs PowerShell 5.1 with .NET Framework 4.7 or later.

**Updates are automatic.** After any command except `update`, the CLI starts `jaaxis update` in its own process, at most once a day (stamp: `~/.jaaxis/update-checked`). `jaaxis update` installs the newest signed release and prints `{"version", "updated", "path"}`. A failed update changes nothing. A development build never updates itself.

**The server can require a newer CLI.** The CLI then updates itself and runs the same command again, once.

## Sign-in

| Command | What it does |
| --- | --- |
| `jaaxis login [--no-browser]` | OAuth 2.1 with PKCE and a loopback redirect, the same consent screen as any MCP client. `--no-browser` prints the URL on stderr; open it on the same machine. |
| `jaaxis logout` | Deletes the stored sign-in and revokes the grant. Prints `{"signed_out", "grant_revoked", …}`. |
| `jaaxis whoami` | Prints `{"server", "account", "connection"}`. |
| `jaaxis version` | Prints `{"version"}`. |

- The sign-in is kept in the OS keychain. A machine with no keychain is not supported.
- `JAAXIS_SERVER` points the CLI at another MCP endpoint (default `https://api.jaaxis.com/mcp`). It must be https, or http to this machine.

## The project folder

The folder holds only the agents you open. `jaaxis agents list` lists every agent, `jaaxis agents files <agent>` lists one agent's files, and `jaaxis grep <text> [--agent <id>]…` searches the files of every agent without opening them. `jaaxis pull [--dir <path>] [<agent_id> [path…]]` opens an agent (or brings one knowledge document by path) into a folder (default `./jaaxis`) and keeps a pristine copy in `.jaaxis/base/`. It prints `{"updated", "kept", "conflicts"}`.

```
AGENTS.md                         how to work in the project
package.json, tsconfig.json       generated
node_modules/@jaaxis/sdk/         the SDK's types, generated
account/instructions.md
agents/<agent_id>/
  AGENTS.md, tsconfig.json        generated
  jaaxis.config.json                the settings, plain JSON with a "$schema" line
  persona.md
  knowledge/*.md
  tools/*.ts
  handlers/*.ts
  tests/*.test.ts
  lib/*.ts
```

`tsc -b` in the folder type-checks every opened agent with no install. An agent that still holds `jaaxis.config.ts` is read as before and saved as `jaaxis.config.json` on its next push; release 2 drops the `.ts` form.

**Which folder.** Without `--dir`, a command run inside a pulled folder (one holding `.jaaxis/base/`), or below it, uses that folder. Otherwise `pull` uses `./jaaxis`. `status`, `diff`, `push`, `add`, `restore` and `test` need a pulled folder; without one they exit 1 with `no pulled folder here or above`.

**Pull is safe to run at any time.**

- A file you have not changed is rewritten from the server.
- A file you changed that did not change on the server is kept.
- A file changed on both sides is left alone and listed under `conflicts`; pull then exits 1. The live version is written to `.jaaxis/server/<path>`.
- `AGENTS.md`, each agent's `AGENTS.md` and `tsconfig.json` are generated: pull always replaces them, they are never conflicts and never pushed.
- Root `package.json`, root `tsconfig.json`, and `node_modules/@jaaxis/sdk` are generated too. A `package.json` or `tsconfig.json` pull did not write (one without its "Generated by jaaxis pull" line) is left as it is, and pull prints what to add to it.
- Paths use only ASCII letters, digits, `-`, `_` and `.`, and no part starts with `.`. A server path outside the tree, or two that differ only in case, refuses the whole pull before anything is written. A local file with another name is refused by `status`, `diff` and `push`.

### Commands on the folder

| Command | What it does |
| --- | --- |
| `jaaxis status [--dir <path>] [--json]` | Lists `modified`, `added`, `deleted` and `conflict` files against the base copy. Local only. `--json` prints `{"modified", "added", "deleted", "conflicts"}`. |
| `jaaxis diff [--dir <path>] [<path>…]` | Unified diff against the base copy; for a conflict, the live change and then your change. Local only. |
| `jaaxis push [-m <message> \| --summary-file <path>] [--dir <path>]` | Saves each agent's changed files as one change per agent: type-check, tests, then save. The message is the change log entry; without one it is `saved from the workspace`. `-m` and `--summary-file` together are refused. |
| `jaaxis test [--agent <id>]` | Runs the project's tests without saving. |
| `jaaxis add handler <event> [--service <name>]\|escalate\|update_labels\|stay_silent\|api [--agent <id>]` | Writes a working file to start from: `handlers/<event>.ts` (events: `message`, `silence <15m–30d>`, `payment.paid`, `booking.<created\|updated\|cancelled\|approved> --service <name>` (one service's booking change, whoever made it; `--service` is its key in `jaaxis.config.json`), `webhook:<connection>`), a built-in tool's `tools/<name>.ts` for code before and after the call, or `api` (a tool that calls an outside service, with its test). Refuses if a file already exists. |
| `jaaxis log [-n <count>] [--agent <id>]` | Lists saved changes, newest first (default 20). |
| `jaaxis restore --from <change-id> [<path>…] [--agent <id>]` | Puts a saved change's files back in the folder; the next `push` saves them. Refuses a file a later change touched. |

Flags go before positional arguments. `push` is sent to `POST /mcp/push` and `add`, `restore` and `test` to `POST /mcp/folder` on the API host, with the folder's files; what `add` and `restore` write comes back and is written into the folder. `--agent` is needed only when more than one agent is in reach.

**Push.**

- `old_text` is the base file whole and `new_text` your file; an empty `old_text` creates a file, an empty `new_text` deletes it.
- On success the saved agent's files and base copies are rewritten from the server, so `status` is clean.
- Each agent is tried; if one is refused, the others are still saved and the exit code is 1.
- If a file moved on the server since the pull, the push is refused and nothing of that agent is saved. The CLI refreshes untouched files, lists the conflicts and writes each live version to `.jaaxis/server/<path>`. Edit your file to keep both changes and push again.

## Other commands

These run on the server. Every one answers `--help`, takes `--json` for JSON output and `--out <path>` to write the output to a file on this machine.

| Command | What it does |
| --- | --- |
| `jaaxis help [<command> \| errors]` | Lists the commands, this program's own included. `help errors` lists every error code and its fix. |
| `jaaxis apply` / `jaaxis discard [n]` | Dashboard assistant only, in ask-first accounts: settle the changes held in this conversation. `apply` does them in order and is refused (`NOT_APPROVED`) until the merchant has answered the list; `discard n` drops item n, `discard` drops all. The CLI and MCP never hold, so here both print `nothing is held in this conversation`. |
| `jaaxis preview --as-customer "<message>" [--conversation <preview-id>] [--agent <id>]` | Talks to the agent as a customer; prints the reply and the tools it used. |
| `jaaxis query "<sql>"` | Runs one read-only SQL statement on the business tables. |
| `jaaxis knowledge search "<question>" [--agent <id>]` | Searches the agent's knowledge the way the agent retrieves it for a customer message, by meaning and across languages. Prints each passage the agent would read, in full, under the file it comes from. |
| `jaaxis support search "<question>"` | Searches the Jaaxis help center. The question goes to a public docs search, so write it generically; one with an email address, a link or a phone number is refused before it is sent. |
| `jaaxis support escalate` | Hands the dashboard assistant chat to the Jaaxis team, who reply in it, usually within 24 hours. Anywhere else it is refused and names support@jaaxis.com. |
| `jaaxis secrets request <NAME> [--reason "<text>"] [--agent <id>]` | Prints a link to a secure field where the merchant sets the named secret (such as `SHOPIFY_TOKEN`) that `jaaxis.config.json` references. No secret ever passes through the CLI. |
| `jaaxis sheets pick [--reason "<text>"] [--agent <id>]` | Prints a link where the merchant picks a spreadsheet in Google's picker. |
| `jaaxis sheets preview …` | Shows a picked spreadsheet's worksheets. |
| `jaaxis <resource> <verb> [flags]` | The business operations: `agents`, `bookings`, `availability`, `conversations`, `messages`, `knowledge`, `labels`, `members`, `products`, `payment-links` and the others `jaaxis help` lists. `jaaxis <resource> --help` lists its verbs, `jaaxis <resource> <verb> --help` its flags. |

An irreversible action waits for the merchant to confirm it in the dashboard. The command says so and exits 1 with `PENDING_CONFIRMATION`; nothing has happened yet.

## The skill

`jaaxis setup [--yes]` installs a short, fixed `SKILL.md` pointing to the pulled folder’s `AGENTS.md`. Setup needs no server fetch. It writes it to:

- `~/.agents/skills/jaaxis/SKILL.md` (Codex and others);
- `$CLAUDE_CONFIG_DIR/skills/jaaxis/SKILL.md`, default `~/.claude/skills/jaaxis/SKILL.md` (Claude Code, Cursor);
- `~/.copilot/skills/jaaxis/SKILL.md`, only when `~/.copilot` exists.

It also allows the CLI once, so the agent does not ask before each command:

- `Bash(jaaxis:*)` in `permissions.allow` of Claude Code's `settings.json`, only when Claude's config folder holds something besides `skills`;
- `rules/jaaxis.rules` under `$CODEX_HOME` (default `~/.codex`), only when that folder exists.

It shows what it will write and asks first; only `y` or `yes` goes ahead (`--yes` skips the question). It prints `{"written", "paths", "effect", "undo", "trust"}`; `undo` says how to remove every file. Start a new coding-agent session to load the skill.

**The folder’s guide stays current.** After a command in a pulled folder finishes its work, successfully or not, the CLI checks any `Jaaxis-Guide-Version` seen on its server responses against the root `AGENTS.md`. Local-only commands make no request and do not refresh the guide. A different hash refreshes the root and each pulled agent’s generated `AGENTS.md` through the same resource read as pull, then prints `updated AGENTS.md to the current Jaaxis guide` on stderr. Merchant files and `CLAUDE.md` stay untouched. A failure prints a warning and leaves the command’s result unchanged. The global signpost needs no refresh.

**Allowing jaaxis lets your coding agent change your Jaaxis agents and send their files to Jaaxis without asking. Only allow it in sessions you trust.**

A coding agent's command sandbox may refuse the network. Allow `jaaxis` network access to the MCP server's host (and GitHub, for updates).

## Output and exit codes

- **stdout** is the command's result.
- A refusal goes to stderr as `error[CODE] where`, what is wrong, what is expected and an example. Exit **1**.
- A usage error exits **2**.
- Signed out, or a sign-in that can no longer be renewed, exits **3**.
- A write whose outcome is unknown says so and tells you to check before retrying.
- Past a server rate limit the command exits 1 with `too many requests … wait a minute, then try again`. Each signed-in user may make 300 MCP requests a minute (a command is several), 60 pushes and 60 folder commands (`add`, `restore`, `test`).
- No command prompts except `setup`.

## Not supported

- CI sign-in: the provider rotates refresh tokens, so a CI job cannot hold a login.
- A machine without an OS keychain.
